## 一、这个技能解决什么问题

用户给一个生日（例如 `1999-12-03`），在抖音上把同一天出生的人找出来，汇总成一张可直接使用的表格。

难点不在搜索，而在三点：

1. **量**：目标生日可能藏在数万乃至十几万条评论里，逐屏滚动翻页效率极低。
2. **写法不统一**：有人写 `991203`，有人写 `99.12.03`，有人只在「99年包厢」楼里回一个 `12.3`。
3. **真假混杂**：同一句里可能夹着农历日期、学号、替朋友报的生日。

技能把这三件事拆成可重复执行的步骤：搜索 → 并发拉取 → 上下文判定 → 去重过滤 → 出表 → 询问是否打开主页。

## 二、用到的插件与依赖

| 类别 | 名称 | 作用 | 是否随包提供 |
|---|---|---|---|
| 浏览器驱动 | `playwright-core`（Node） | 通过 CDP 接管本机 Edge/Chrome，执行页面操作与接口重放 | 是，`vendor/node_modules/playwright-core` |
| 浏览器技能 | `browser-cdp` | 通用浏览器接管说明（打开页面/读正文/点击/截图） | 是，`vendor/skills/browser-cdp/` |
| 文档生成 | `python-docx` | 生成横版 A4 Word 表格 | 否，需运行环境已安装 |
| 表格生成 | `openpyxl`（可选） | 需要 Excel 版时导出 xlsx | 否，可选安装 |
| 版面校验 | `pymupdf` + 办公软件导出 PDF | 渲染成图，检查表格是否溢出 | 否，仅开发调试用 |
| 系统能力 | CDP（Chrome DevTools Protocol） | 创建独立窗口、多标签、设置窗口尺寸 | 内置，无需安装 |

> 打包的 `playwright-core` 不含浏览器内核，调用本机已安装的 Edge/Chrome，因此压缩包只有几 MB。

## 二·补充、新用户首次使用：依赖自举

技能包已内置 `playwright-core`，多数情况下解压即可用。若使用者环境缺少浏览器操控依赖，按以下顺序自动补齐，不需要人工判断：

```
scripts/check_env.py          # 自检：Python/Node/npm/浏览器/playwright-core
        │ 缺 Python 包
        ├── check_env.py --fix          → pip install python-docx openpyxl
        │ 缺 playwright-core
        └── vendor/scripts/setup_deps.mjs
                 ├─ 1. 随包自带 vendor/node_modules/playwright-core   ← 优先，离线可用
                 ├─ 2. npm install playwright-core@^1.65.0            ← 官方源
                 └─ 3. GitHub 兜底：克隆 https://github.com/microsoft/playwright
                        并构建 packages/playwright-core 复制进 vendor/node_modules/
```

| 缺失项 | 处理方式 |
|---|---|
| Python 包 | `check_env.py --fix` 自动 pip 安装 |
| Node.js | 安装 Node.js 18+（nodejs.org）后重跑自检 |
| playwright-core | `setup_deps.mjs` 三级策略自动处理 |
| Edge / Chrome | 安装任一浏览器；技能直接驱动本机浏览器，不额外下载内核 |

自检最后一行显示「全部就绪」才进入采集流程。**未通过自检不要直接开抓**，否则会在启动浏览器这一步反复失败。

## 三、写了哪些脚本

### Python（`scripts/`）

| 脚本 | 职责 | 关键实现 |
|---|---|---|
| `init_task.py` | 解析生日、生成 `config.json` | 把日期转成 11 条正则（六位/八位连写、分隔符、中文年月日、年+月日、裸月日、锚点、农历），供 JS 与 Python 共用 |
| `filter_accounts.py` | 判定、去重、过滤 | 按优先级匹配；锚点楼回复用父楼层补年份；剔除农历；按 cid 与「昵称+文本」双重去重；输出 `accounts.json` + `report.txt` |
| `build_docx.py` | 生成横版 A4 表格 | 横向节、列宽按内容分配、表头跨页重复、隔行底色、页脚页码、两表各自另起一页；`--xlsx` 可同时导出 Excel |

### Node（`vendor/scripts/`）

| 脚本 | 职责 | 关键实现 |
|---|---|---|
| `launch_browser.mjs` | 启动可调试浏览器 | 复制默认 profile 的 Cookies 到独立目录（绕过 Edge 的非默认目录限制）；后台保活，避免进程被回收 |
| `search_videos.mjs` | 搜索生日合集视频 | 拦截 `general/search/single` 响应，滚动两轮收集候选，按评论数排序 |
| `pull_comments.mjs` | 拉评论 + 锚点楼回复 | 捕获真实请求作模板 → 页面内 `fetch` 改 `aweme_id`/`cursor` 并发翻页（8 路×20 条）→ 识别锚点楼层 → 拉 `/comment/list/reply/` |
| `open_profiles.mjs` | 单窗口多标签打开主页 | CDP 建标签 → 关闭散窗 → 标题改成「序号 昵称」并定时守护 → 清除登录遮罩 → 逐页激活、异常自动刷新 |

## 四、流程与数据流

```
生日字符串
   │  init_task.py
   ▼
config.json（日期 + 关键词 + 全部正则）
   │  launch_browser.mjs
   ▼
可调试浏览器（CDP 端口，带登录态）
   │  search_videos.mjs
   ▼
videos.jsonl（按评论量排序的候选视频）
   │  pull_comments.mjs
   ▼
comments.jsonl（主评论 + 锚点楼回复，含父楼层文本）
   │  filter_accounts.py
   ▼
accounts.json（结构化名单） + report.txt（命中统计）
   │  build_docx.py
   ▼
<日期>生日_抖音账号汇总.docx（横版 A4 表格）
   │  【询问用户】是否需要打开主页
   ▼
open_profiles.mjs → 单窗口多标签
```

## 五、关键设计决策

**为什么用接口重放而不是滚动抓取**
滚动一屏只触发一页请求，页面还容易崩；捕获一条真实请求后在页面内直接 `fetch`、改 `cursor` 并发翻页，实测服务端不校验签名参数，速度可提升一个数量级。

**为什么必须用独立 profile**
Edge/Chrome 136+ 拒绝在默认用户目录上开调试端口（会直接退出）。复制 `Local State` 与 `Network/Cookies` 到独立目录即可保留登录态，同时满足「非默认目录」要求，不影响用户日常浏览器。

**为什么要「锚点楼」这一层**
大量用户只回 `1203`、`12.3` 这类月日。只有当父楼层是「99年集合 / 99年包厢 / 99年12月」时年份才确定。技能因此专门识别锚点楼层并单独拉取全部回复，用上下文把简写补全。

**为什么表格用横版 A4**
七列信息（昵称/抖音号/评论原文/位置/点赞/来源）在竖版里必然挤压折行。横版可用宽度约 25.7cm，评论原文能一行放下，几十行也只需两页。

**为什么最后一定要问一句**
几十个标签页占用大量内存，且打开页面属于用户可视行为。技能规定：未得到同意不得自动开页面。

## 六、能力范围与性能特征

| 维度 | 说明 |
|---|---|
| 单视频采集量 | 受平台限流约束，单账号单次连续拉取建议不超过约 8 万条 |
| 并发 | 默认 8 路 × 20 条/批翻页，可按机器与网络情况调整 |
| 覆盖范围 | 仅覆盖 Web 端可见评论；App 端部分折叠回复可能缺失 |
| 输出规模 | 命中数量取决于目标生日的热门程度，从个位数到数十人不等 |
| 运行前提 | 本机已装 Edge/Chrome 并登录抖音（仅影响能否查看完整主页） |

## 七、局限与后续可加

- 深评论区（最新评论）可能仍有未覆盖用户，可提高采集上限或隔时段补拉。
- 可选增强：OCR 识别「生日截图」类评论；按 IP 属地、粉丝数二次筛选。
- 结果涉及真实用户信息，交付时必须附隐私提醒，并建议使用后删除原始数据。
