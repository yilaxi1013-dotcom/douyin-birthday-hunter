# 判定口径与正则设计

> 文中示例统一使用出生日期 `1999-12-03`（六位写法 `991203`）。实际执行时由 `init_task.py` 按目标日期生成，不需要手改。

## 为什么只认「年份+月日」

抖音评论区报生日有两种习惯：

1. **完整版**：`991203`、`99.12.03`、`99年12月3`、`1999 12.03` —— 年份与月日同时出现，可直接判定。
2. **简写版**：`1203`、`12.3`、`12月3日` —— 只报月日。

简写版单看无法确定年份，但**只要它出现在「99年集合 / 99年包厢 / 99年12月」这类楼层下面，年份就由父楼层确定**。这是本技能的核心技巧：用楼层上下文补全缺失的年份。

## 判定优先级

| 级别 | 依据 | 置信度 | 是否入主表 |
|---|---|---|---|
| A | 八位连写 `19991203` | 最高 | 是 |
| A | 六位连写 `991203` | 最高 | 是 |
| B | 分隔符 `99.12.03` / `99-12-03` / `99/12/03` | 高 | 是 |
| B | 文字 `99年12月3` / `1999年12月3日` | 高 | 是 |
| B | 年+数字 `1999 12.03` / `12.03 1999` | 高 | 是 |
| C | 锚点楼下回 `1203` / `12月3日` | 中 | 是，标注「锚点楼确认」 |
| D | 全局裸月日 `1203` / `12.3` | 低 | 否（单独统计） |
| — | 含「农历 / 阴历 / 旧历」 | — | 否，剔除 |

## 正则设计要点

`scripts/init_task.py` 的 `build_patterns()` 会按给定日期生成全套正则，输出到 `config.json`，供 JS 与 Python 共用。

设计约束：

1. **只用定长 lookbehind**。Python `re` 不支持变长 lookbehind，所以写成 `(?<!\d)`、`(?<![\d.])`，长度固定为 1。
2. **边界必须卡死**。六位连写要加 `(?!\d)`，否则更长的数字（学号、QQ 号）会误命中；带分隔符的写法要加 `(?![\d.])`，避免把 `99.12.030` 这类截断命中。
3. **年份三种写法**：`1999`、`99`、`9`（有人写 `9年`）。月日同理，需兼容 `03` 与 `3`。
4. **年份与月日之间的间隔**用 `[^\n]{0,12}`，允许「99年的12月3日」这类插入文本，但**不允许跨行**。
5. **农历先行剔除**。同一句里既有公历写法又有「农历」字样的，一律丢弃——农历与公历不是同一天。

## 常见误报

| 现象 | 例子 | 处理 |
|---|---|---|
| 学号/QQ号/手机号 | `9912034567` 这类长数字 | 连写模式加 `(?!\d)` 边界，长数字不命中 |
| 农历生日 | `99年农历12月3` | 农历关键词剔除 |
| 别人报的生日 | `我朋友99.12.03` | 保留但需人工复核；表格里保留原文供判断 |
| 日期区间 | `12.3-12.5` | 需人工看原文；正则只保证不跨数字误命中 |

## 去重规则

1. 同一 `cid` 只保留一条（接口翻页重叠导致）。
2. `昵称 + 文本` 完全相同视为同一人重复留言，只保留点赞更高的一条。
3. 无昵称且文本与已有记录重复的，丢弃（接口偶发缺用户字段）。

## 数据合规提示

采集结果属个人信息范畴，应仅在合法正当场景使用；不得公开传播、售卖或用于骚扰。使用完毕后建议删除 `comments.jsonl` 等原始数据。
